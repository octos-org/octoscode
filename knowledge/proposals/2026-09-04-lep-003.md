# 进化环:外环把内环摩擦编译成缺陷记录,经 issue 关口修 harness

## Context

OctoLoop 双环已跑过多场战役,每场都沉淀出规程纪律,但沉淀方式是人肉复盘写
散文,触发时机是事故之后。内环 octoscode 与 octos serve 的 harness 缺陷被反复
踩到又反复遗忘:预算耗尽静默收工、围栏 peer 冷编译耗尽迭代、goal 工具被陈旧
卡态挡住(2026-09-04 #45 战役同一天复现后两条,已立 octos #2236、#2237)。
缺的不是想法,是把"事故后靠记忆复盘"变成"事件发生时落卡、外环定期收割、
缺陷进 issue 账本"。设计全文见 artifact
<https://claude.ai/code/artifact/d0008fdb-c387-47ca-8dec-2195f826e1f0>(v2,
已并入 Codex 与 Grok Build 的对抗评审)。

借鉴两篇论文:Harness-of-Harness(arXiv 2609.01481)的"代码状态与证据状态
分离、issue 作跨轮账本、冻结候选只读评估";HarnessFix(arXiv 2606.06324)的
"轨迹到 harness 产物的锚点、跨任务合并再修、算子表约束修复、回归感知验收"。

## Motivation

agent 不能凭空回答"哪里可以改进",但它可靠能答"我在哪被卡住、被推翻、被证伪、
耗尽预算"。前者是判断,后者是感知。把感知机械化放在外环侧脚本,把判断集中在
持主审锁的贵模型上,把修复交回便宜内环,与双环的成本错配是同一逻辑。

## Goals

- 外环侧采集哨从三个既有来源(活板、events.jsonl、MCP 审计板)增量落卡,幂等。
- 缺陷记录与修复记忆集中在本仓库 `knowledge/context/evolution/`,按 `repo`
  字段路由 issue 与修复到缺陷所在仓库。
- 缺陷记录升格必须先开 GitHub issue,维护者 triage 接受才进规格与派单。
- 阶段 0 只读影子试点:不改运行时,不改协议,不改 MCP 工具面。

## Non-Goals

- 不改模型,不做 prompt 搜索式优化。
- 不由 agent 改 R1 到 R7 语义、协议版本、推送权、免沙箱、权限配置、树主权谓词。
- 不自动写 ACK:进化信号与 R1 回执分立。
- 不新增 events.jsonl kind(事件由 octos serve 发射,kind 集合归 REQ-OLP-OBS)。
- 不新增 MCP 工具,不改 `~/.octos/outer/mcp/` 运行态路径。

## Decision

叠在双环上的一条慢环,六个环节、四种记录、一张 authority 表:

1. **采集**:`scripts/olp-evo-harvest.sh` 由外环运行(触发器贴 R1 v1 定式与 `olp_mcp.rs` 真实审计行形,不用任意子串),读活板
   `<repo>/.octos/OUTER_LOOP_REVIEW.md`(`docs/` 同名文件是冻结快照,不读)、
   实例 `events.jsonl`、`~/.octos/outer/OUTER_LOOP_MCP.md`;游标与取号在
   `~/.octos/outer/evo/` 的同一把锁内提交;卡片经 `olp-board-append.sh` 追加到
   `<repo>/.octos/EVOLUTION.md`。卡只记症状与证据信封,不写建议。
2. **诊断**:持 outer-duty 锁的主审运行 retro(阶段 1 拟在 `/octoloop` skill 的 outer 模式下新增的工作流入口,当前不存在),
   回溯责任步、归 ETCLOVG 七层、锚到可编辑产物、同根因合并、跨 goal 复发计数。
3. **立案**:跨 goal 复发 ≥ 2 或 S1 严重度时起草 GitHub issue;发布是对外动作,
   operator 一键或明示委托。
4. **规格**:issue 被 triage 接受后,主审从算子表选算子,写允许/禁止/必需行为
   三段规格,固定禁改段随附。
5. **修复**:规格转 agent-spec 契约,落目标仓库活板派单;内环在围栏 worktree
   实现,主树禁止 checkout 修复分支。
6. **验收**:候选以 commit OID、tree hash、夹具摘要固定;回放夹具是硬门,
   战役指标是有期限的观察窗;接受与拒绝都进记忆,根因指纹去重,rejected 粘性。

Authority:采集哨只写进化黑板;持锁主审才能合并、立案、写规格、终审、写记忆;
第二外环只出署名异议;分歧升 operator;规程产物、协议版本、REQ、权限分类器、
树主权谓词只归 operator。

## Compatibility

- CLI and public API:新增一个 bash 脚本,无 CLI 变更。
- File formats:新增 `.octos/EVOLUTION.md`(外环私有工作纸,不入库;本仓库
  `.octos/` 整目录已忽略)、`~/.octos/outer/evo/cursor.json`、
  `knowledge/context/evolution/*.md`(context 类型,不进 artifact lint)。
- Existing specs and KLL artifacts:不改 OLP 协议正文与附录、不升版本;不改
  REQ-OLP-OBS、REQ-OLP-MCP。前置漂移(operator 单独整改,阶段 0 不碰):
  `AGENTS.md` 头部已是 `protocol: olp/v2` 但仍指向 `docs/OUTER_LOOP_REVIEW.md`;
  `.octos/loop.md` 仍标 olp/v0 且指向 `docs/` 快照;契约测试钉的是 `docs/` 路径。
  进化采集只读 `.octos/` 活板,不混用两套标签。

## Migration Plan

N/A -- no migration required(旧卡片不存在;`OUTER_LOOP_MCP.md` 保留原样)。

## Security Considerations

新读面是活板、事件流、MCP 信箱。卡片只存指针与摘要,不复制 MCP 的 question、
context、tried 正文;issue 正文由主审起草、operator 发布前过目,禁止带凭据与
私有路径。采集脚本对三源只读,对活板零写入。

## Privacy Considerations

回放夹具从战役轨迹制作时必须脱敏,入库前主审核对不含会话内容与密钥。游标与
卡片只含路径、行号、摘要、时间戳。

## Risks and Assumptions

### Assumptions

- 三源格式稳定:ACK v1 定式由契约测试钉住;events.jsonl 字段由 REQ-OLP-OBS
  钉住;MCP 审计板由 `olp_mcp.rs` 写。Invalidated if: 任一来源改格式而未升版。
- events.jsonl 只追加不轮转。Invalidated if: 后续提案引入轮转(届时游标加
  截断检测已就位)。

### Risks

- 卡片噪音淹没诊断。Mitigation: 无信封作废;取号去重;每次 retro 最多三条。
- 指标诱导内环装死。Mitigation: `ask_outer`/`ACK(blocked)` 只作分母不作 KPI。
- 双主竞态。Mitigation: authority 表,未持锁不得写记录。
- 会话猝死丢现场。Mitigation: 状态全部在文件,禁止落 /tmp。

## Consequences

Good, because 反复踩的 harness 坑第一次有了机械采集、跨战役复发计数和 issue
账本,修复有边界、验收有硬门。
Bad, because 多一块黑板、一份游标状态和一个持久目录要维护;retro 是贵模型
成本,必须绑预算档。

## Alternatives Considered

- 让内环自报"哪里可以改进":便宜模型连 ACK 定式都要契约测试钉住,靠自觉收
  不到信号。已拒绝。
- 只改 prompt 与 skill 卡的进化:HarnessFix 消融里只改 prompt 是最差变体。
  已拒绝,进化必须可触及运行时代码,但只经 issue 与规格。
- 进化黑板写进 OLP 协议附录:协议开篇"不发明新机制",R6 信道语义变更必须
  升版。已拒绝,进化黑板定位为外环私有工作纸。
