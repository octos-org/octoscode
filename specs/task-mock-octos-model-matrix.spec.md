## Intent

Every byte in `examples/automation/octos` comes from one model. The capture is
`deepseek / deepseek-v4-pro` — a reasoning model on an `openai`-shaped route with
a 1048576-token window — so its single turn is 20 `reasoning_delta` followed by
13 `assistant_delta`, its `token_cost_update` names that model at that window,
and `session_status_read.usage` is `{}`. Every model-varying client path is
therefore unexercised: a model that emits no reasoning at all, an
`anthropic`-shaped route, a window small enough for the `/context` percentage to
mean anything, a primary with no key, and a fallback that is actually selected.
This task adds a coherent per-model data set for several models the client
already knows, and drives them with the shared scenario loop runner.
Implementation repo is **wasm_mock_rust**
(`/Users/alanpoon/Documents/go/wasm_mock_rust`); this contract ships with the
workstream.

## Decisions

- A model case is a **multi-file scenario**, not a new `index.json` entry. No new
  method is being mocked — the same three files simply have to move together, or
  the client sees one model in the llm list and another in the stream.
  `gen_scenario.py` already supports this: `FILES` maps `llm`, `status` and
  `turn` to the three files (line 19), and a scenario already returns a
  multi-area dict (line 385). A model scenario returns
  `{"llm": …, "status": …, "turn": …}`.
- Model scenarios register under the existing `llm` area, so the shared runner
  drives them as `run_campaign.py llm` and no new area is introduced.
- The matrix, every model one the client already carries in
  `src/menu/providers.rs`:

  | scenario | model | what it forces |
  | `model-kimi-no-reasoning` | `moonshot / kimi-k2.6` | zero `reasoning_delta`; the reasoning block must not render at all |
  | `model-glm-small-window` | `zai / glm-4.7` | a small `context_window`, so the `/context` subtitle percentage is non-trivial |
  | `model-claude-anthropic-route` | `anthropic / claude` | `route.api_type` is `anthropic`, not `openai` |
  | `model-deepseek-reasoner-heavy` | `deepseek / deepseek-reasoner` | `reasoning_delta` far outnumbering `assistant_delta` |
  | `model-fallback-selected` | primary unavailable, fallback `selected` | the client routes to the fallback |
  | `model-primary-no-key` | primary `has_api_key` false, `available` false | the client must not present it as usable |

- Every scenario stays internally consistent: the `token_cost_update` `model`
  equals the llm-list primary's `model`, `context_window` equals that model's
  own window, and `session_cost` is recomputed rather than inheriting the
  captured `0.21267676000000008`. A cost or window that belongs to a different
  model is exactly the incoherence this data set exists to rule out.
- `session_status_read.usage` is `{}` in the capture. Each model scenario fills
  it so it agrees with that scenario's `token_cost_update` instead of staying
  empty.
- Streams are synthesized through the existing `projection/envelope` helper
  (`gen_scenario.py:196`), not hand-written JSON, so a payload shape change is
  made in one place.
- Envelope `seq` is renumbered contiguously from 1 in every generated stream, the
  rule `turn_stream.json` already follows, because the client reports `seq` gaps
  as `protocol/replay_lossy`.
- The loop runner is `examples/automation/octos/run_campaign.py <area>`, shared
  with the `/context` and `/dock` contracts — whichever lands first creates it,
  and this one passes `llm`. Per scenario it installs, deploys with
  `bash cli/mock_octos.sh`, reads `server/heartbeat`, asserts the reported
  `scenario_id` equals the one just installed, drives the client, collects the
  report, and restores the baseline in a finally block.
- The heartbeat assertion runs before any driving. `shutil.copy2` preserves
  source mtimes, cargo then skips the rebuild, and a campaign once tested one
  stale build fifty times while every deploy reported `ok`.
- The committed tree stays at the recorded deepseek baseline. Model data is
  generated by installing a scenario, never by editing the baseline files in
  place.
- No octoscode source changes. A client that mishandles a served model is a
  finding this contract reports, not a fix it makes.

## Boundaries

### Allowed Changes
- examples/automation/octos/gen_scenario.py
- examples/automation/octos/run_campaign.py
- examples/automation/octos/test_model_matrix.py
- examples/automation/octos/README.md
- examples/automation/octos/pristine/**

### Forbidden
- Do not commit `profile_llm_list.json`, `session_status_read.json` or
  `turn_stream.json` with a scenario installed; the committed tree must be the
  recorded baseline.
- Do not add an `index.json` entry — this task mocks no new method.
- Do not hand-write stream JSON; generate it through the envelope helper.
- Do not leave a `token_cost_update` naming a different model than the llm list.
- Do not hardcode an absolute machine path anywhere in the runner.
- Do not modify any file under the octoscode repository's `src/`.

## Out of Scope

- Calling any real provider endpoint; live billability is a separate contract.
- Adding a model or route to octoscode itself.
- A pricing table; `session_cost` values are fixtures, not a cost engine.
- The `/model` and `/provider` menu flows and their RPCs.
- Streaming throughput or latency characteristics per model.
